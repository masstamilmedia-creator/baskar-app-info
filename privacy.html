GOOGLE DRIVE DATA & LOCAL STORAGE

Privacy policy

Privacy information for the personal-use BASKAR One Repository Backup OAuth application and its desktop File Distribution Desk workflow.

Data accessed and purpose

With the account owner's authorization, the desktop application accesses Google Drive folder/file names, identifiers, paths and available metadata to browse destinations and detect ambiguous names. It uploads user-selected file contents and downloads destination file contents to check duplicates and verify SHA-256 hashes. Temporary local snapshots and readback files support this verification.

Authorization and local records

OAuth client settings and account tokens are stored in local rclone configuration files on the owner's computer. Application settings store account display labels and favorite destinations. Operation history can contain local file paths, destination paths, hashes, outcomes, error information and references to configuration-file paths. These records should be treated as private. Account tokens are not intended to be included in operation logs or website files.

The account setup command-line wizard can display credentials. The owner should not share its full output, configuration files or token-bearing screenshots.

Transfers and service providers

Selected contents are sent to the Google Drive destination chosen by the owner. The separate repository publishing workflow can send approved project artifacts to GitHub when the owner explicitly starts that workflow. The desktop tool is not intended to sell Google user data, use it for advertising, or use it to train generalized AI models. It does not deliberately transfer Drive data to this informational website.

Google and GitHub process information under their own service terms and privacy policies. Google Drive folder sharing settings continue to apply to uploaded files; this tool does not make an otherwise shared folder private.

Storage, retention and security

The owner controls source files, downloaded copies, local settings, history and cloud destinations. Records and uploaded files remain until the owner removes them using the appropriate local or cloud controls. Temporary transfer files are normally cleaned up by the workflow, but interruptions may require local review.

Google API transfers use provider-supported secure connections. Local rclone configurations are not claimed to be encrypted by default; new-account directories are restricted to the Windows account, administrators and system by the setup routine. The owner is responsible for device access, backups and protection of credentials.

Account controls and deletion

The owner can revoke authorization through Google Account security settings and stop using a connection in the desktop tool. Revoking access does not delete files already uploaded to Drive or local operation history. Cloud files can be deleted in Google Drive; local history and settings can be removed separately after reviewing any recovery needs.

Google API commitments

Use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

This website

These static pages contain no application login, upload form, analytics script or advertising script. If hosted on GitHub Pages as proposed, GitHub records visitor IP addresses for security under its own privacy practices.
